## 1. Executive Summary

Empirical audits by Challenger 2 and Reviewer 1 identified three layout and rendering defects in the core platform editor:
1. **Defect 1 (Text Overflow & Layout Bleeding)**: Administrative table cells in fixed-table layouts lack word-breaking rules. Long uninterrupted administrative symbols (e.g. `Số: 125/VCNM-TTTN/2026/TB-TKV-KĐAT`) or acronyms bleed horizontally across cell boundaries into adjacent columns.
2. **Defect 2 (CSS Specificity Invalidation)**: Inline `style="width: ...px"` generated by Tiptap's `colwidth` attribute has specificity (1, 0, 0, 0), overriding external stylesheet percentage widths (40%/60% and 50%/50%) which have specificity (0, 0, 2, 1). This breaks proportional scaling across custom margins, zoom levels, and print.
3. **Defect 3 (Horizontal Canvas Clipping on Viewports < 1200px)**: The A4 canvas scroll container uses `overflow-y-auto` while its parent `<main>` uses `overflow-hidden`. On screens < 1200px with the 384px sidebar open, the 794px (210mm) A4 sheet is horizontally clipped with no scrollbar available.

This document formulates the exact remediation code, CSS specificity arithmetic, flexbox overflow mechanics, and verification tests.

## 2. Remediation 1: Prevent Table Cell Text Overflow

### 2.1 File & Location
- **Target File**: `web_app/src/styles/a4-canvas.css`
- **Lines Affected**: 27–33

### 2.2 Root Cause Analysis
- In `a4-canvas.css:19-25`, `.tiptap-table.borderless-table` declares `table-layout: fixed`.
- In CSS fixed table layout, column widths are governed by the first row rather than cell content.
- When unbroken text strings (Vietnamese administrative file reference numbers e.g. `125/VCNM-TTTN/2026/TB-TKV-KĐAT`, email addresses, URLs, or long compound acronyms) exceed the 40% column width (~66mm / ~250px), the browser's default behavior (`overflow-wrap: normal; word-break: normal;`) causes text to overflow the cell bounding box.
- Without `overflow: hidden`, this text overflows into column 2, colliding visually with the National Motto ("CỘNG HÒA XÃ HỘI CHỦ NGHĨA VIỆT NAM").

### 2.3 Proposed Changes
Add `overflow-wrap: break-word;`, `word-break: break-word;`, and `overflow: hidden;` to `.tiptap-table.borderless-table td`.

#### Before (`a4-canvas.css:27-33`):
```css
.tiptap-table.borderless-table td {
  padding: 2px 4px;
  vertical-align: top;
  box-sizing: border-box;
  border: 1px dashed rgba(203, 213, 225, 0.7);
  transition: border-color 0.15s ease;
}
```

#### After (`a4-canvas.css:27-36`):
```css
.tiptap-table.borderless-table td {
  padding: 2px 4px;
  vertical-align: top;
  box-sizing: border-box;
  border: 1px dashed rgba(203, 213, 225, 0.7);
  transition: border-color 0.15s ease;
  overflow-wrap: break-word;
  word-break: break-word;
  overflow: hidden;
}
```

### 2.4 Technical Mechanics
- `overflow-wrap: break-word`: Allows inline text to break at arbitrary grapheme clusters when no permissible breakpoint (space, hyphen) exists within the line. This inherits automatically to all child `<p>`, `<span>`, and `<strong>` elements inside `td`.
- `word-break: break-word`: Provides WebKit and Chromium fallback compatibility in fixed table layout contexts (specifically inside WebView2 / Office Web runtimes).
- `overflow: hidden`: Establishes a strict box constraint on the cell. Even if non-text inline content (SVG lines, embedded icons, or non-wrapping elements) exceeds cell width, it is strictly clipped rather than bleeding into neighboring cells.

## 3. Remediation 2: Fix Specificity Collision on Column Ratios

### 3.1 File & Location
- **Target File**: `web_app/src/styles/a4-canvas.css`
- **Lines Affected**: 45–61

### 3.2 Root Cause Analysis
- In `web_app/src/editor/extensions.ts:338-344`:
  ```ts
  renderHTML: (attributes) => {
    if (!attributes.colwidth) return {};
    return {
      'data-colwidth': attributes.colwidth.join(','),
      style: `width: ${attributes.colwidth[0]}px`,
    };
  },
  ```
- Default documents (`schema.ts:22, 115, 303, 406`) assign pixel widths to cells:
  - Header Table Cell 1: `colwidth: [250]`
  - Header Table Cell 2: `colwidth: [374]`
  - Footer Table Cell 1: `colwidth: [312]`
  - Footer Table Cell 2: `colwidth: [312]`
- This causes ProseMirror to render inline styles: `<td style="width: 250px">`.
- Specificity comparison:
  - Inline style: `(1, 0, 0, 0)`
  - CSS rule `.tiptap-table.admin-header-table td:first-child`: `(0, 0, 2, 1)`
- Because `(1, 0, 0, 0) > (0, 0, 2, 1)`, the inline pixel width overrides the CSS percentage width (`width: 40%`).
- Consequence: When page margins change (e.g. left margin 30mm -> 35mm), or when printed on different paper sizes, the columns remain locked at static pixel dimensions instead of maintaining the 40%:60% (Header) or 50%:50% (Footer) ratio required by NĐ 30/2020.

### 3.3 Proposed Changes
Add `!important` to all four column width rules in `a4-canvas.css`.

#### Before (`a4-canvas.css:45-61`):
```css
/* Header Table Ratio (40% - 60%) */
.tiptap-table.admin-header-table td:first-child {
  width: 40%;
}

.tiptap-table.admin-header-table td:last-child {
  width: 60%;
}

/* Footer Table Ratio (50% - 50%) */
.tiptap-table.admin-footer-table td:first-child {
  width: 50%;
}

.tiptap-table.admin-footer-table td:last-child {
  width: 50%;
}
```

#### After (`a4-canvas.css:45-61`):
```css
/* Header Table Ratio (40% - 60%) */
.tiptap-table.admin-header-table td:first-child {
  width: 40% !important;
}

.tiptap-table.admin-header-table td:last-child {
  width: 60% !important;
}

/* Footer Table Ratio (50% - 50%) */
.tiptap-table.admin-footer-table td:first-child {
  width: 50% !important;
}

.tiptap-table.admin-footer-table td:last-child {
  width: 50% !important;
}
```

### 3.4 Technical Mechanics & Scope Isolation
- In CSS cascade rules, an author declaration marked `!important` overrides normal inline styles that do not have `!important`.
- Tiptap's `AdministrativeTableCell.renderHTML` generates normal inline styles (`style="width: 250px"` without `!important`).
- Adding `!important` to the CSS percentage rules ensures the browser enforces `40%` / `60%` and `50%` / `50%` regardless of any `colwidth` attributes on the AST nodes.
- **Scope Isolation**: Regular tables (`tableType === 'content'`) do not receive `.admin-header-table` or `.admin-footer-table` classes. Therefore, user-defined column resizing and explicit pixel widths in regular content tables remain 100% unaffected.

## 4. Remediation 3: Fix Horizontal Scroll on Viewports < 1200px

### 4.1 File & Location
- **Target File**: `web_app/src/components/editor/A4Canvas.tsx`
- **Lines Affected**: 26–29

### 4.2 Root Cause Analysis
- The A4 sheet component (`A4Canvas.tsx:37-46`) specifies:
  `style={{ width: '210mm', minHeight: '297mm', ... }}`
  At standard 96 DPI, `210mm` = 793.7px (~794px).
- Container padding `px-4` adds 32px, requiring a minimum width of `826px`.
- In `web_app/app/page.tsx:100-122`:
  - Main container: `<main className="flex-1 flex flex-col overflow-hidden bg-slate-100">`
  - Sidebar: `<Sidebar ... className="w-96 ...">` (384px width).
- On screens <= 1200px (e.g. 1024px laptop/tablet):
  `Available width = 1024px - 384px = 640px < 826px`.
- Because `A4Canvas.tsx:27` used `overflow-y-auto`, the scroll container only provided vertical scrollbars. With the parent `<main>` set to `overflow-hidden`, the right portion of the A4 document (~186px) was completely clipped and inaccessible to the user.

### 4.3 Proposed Changes
Update `A4Canvas.tsx` line 27 from `overflow-y-auto` to `overflow-auto`.
Defensively include `m-auto` on the inner relative sheet wrapper to ensure safe flex centering without coordinate cutoff.

#### Before (`A4Canvas.tsx:26-30`):
```tsx
  return (
    <div
      className={`a4-canvas-scroll-container bg-slate-200/70 overflow-y-auto py-8 px-4 flex justify-center min-h-full ${className}`}
      data-testid="a4-canvas-container"
    >
      <div className="relative">
```

#### After (`A4Canvas.tsx:26-30`):
```tsx
  return (
    <div
      className={`a4-canvas-scroll-container bg-slate-200/70 overflow-auto py-8 px-4 flex justify-center min-h-full ${className}`}
      data-testid="a4-canvas-container"
    >
      <div className="relative m-auto">
```

### 4.4 Technical Mechanics
- `overflow-auto` enables both vertical and horizontal scrollbars whenever content exceeds container dimensions.
- **Scrollbar Styling**: `web_app/app/globals.css:20-33` already defines:
  ```css
  ::-webkit-scrollbar {
    width: 6px;
    height: 6px;
  }
  ::-webkit-scrollbar-thumb {
    background: #cbd5e1;
    border-radius: 9999px;
  }
  ```
  `height: 6px` applies directly to the horizontal scrollbar track and thumb, giving it a sleek, unobtrusive design.
- **Flexbox Centering Safeguard (`m-auto`)**:
  In CSS Flexbox, when a container has `justify-content: center` (`justify-center`), overflowing children overflow symmetrically in both directions. In standard LTR reading order, horizontal scrollbars only navigate positive coordinates (`scrollLeft >= 0`), making the left overflow unreachable ("loss of left content").
  Adding `m-auto` to the child `<div className="relative m-auto">` leverages standard CSS flex margin absorption:
  - When viewport width > 826px: positive free space is absorbed by `m-auto`, keeping the A4 sheet centered.
  - When viewport width < 826px: free space becomes negative, auto margins collapse to 0, and the document naturally aligns to the left edge with padding. The user can scroll smoothly across the entire 0px–794px range without any margin clipping.
- **Print Isolation**:
  In `web_app/src/styles/a4-canvas.css:94-99`:
  ```css
  @media print {
    .a4-canvas-scroll-container {
      background: transparent !important;
      padding: 0 !important;
      margin: 0 !important;
      overflow: visible !important;
    }
  }
  ```
  `overflow: visible !important` prevents scroll container clipping during browser printing.
